# AGENTS.md — portafolio

Personal portfolio with two audiences: `/` is the job/technical profile and `/servicios` is the business landing (pages, catalogs, online stores). React Router 7 (framework mode, SSR + prerender), React 19, Tailwind CSS 4 (CSS-first), Motion, TypeScript. Content is Spanish; all copy and personal data live in `app/data/site.ts`.

## Commands

- `npm run dev` — Vite dev server.
- `npm run typecheck` — runs `react-router typegen && tsc`. Never run bare `tsc`: `./+types/*` imports in the route modules (`app/routes/*.tsx`, including the demo pages) are generated into gitignored `.react-router/types`.
- `npm run build` — prerenders `/`, `/servicios`, the Retromaquinas and Forja PC demos, and the seed Pulso catalog/category/product pages into `build/client/` plus `build/server/index.js`; also copies `public/` into `build/client/`.
- `npm start` — `react-router-serve ./build/server/index.js`; requires `npm run build` first.
- No test, lint, or formatter exists. Verify with `npm run typecheck` then `npm run build`; do not invent test commands.

## Structure

- Routing is config-based: `app/routes.ts` declares `index("routes/home.tsx")`, `route("servicios", "routes/services.tsx")`, `route("demos/retromaquinas", ...)`, nested `route("demos/forjapc", ...)` with five child pages, and nested `route("demos/pulso", ...)` with catalog, category, product, search, and admin pages; a file under `app/routes/` alone does nothing. `react-router.config.ts` sets `ssr: true` and prerenders the public/static pages plus the seed Pulso category/product paths — add new routes there if they should ship as static HTML.
- The home is `app/routes/home.tsx`, composed from `app/components/*` in order Hero, About, Projects, Skills, Experience, Contact. Section anchors are Spanish (`#inicio`, `#sobre-mi`, `#proyectos`, `#habilidades`, `#experiencia`, `#contacto`); keep `Navbar` links and section `id`s in sync.
- `/servicios` is `app/routes/services.tsx`, composed from `Services*` components: hero, plans, demos, cases, process, conditions, FAQ, then `Contact variant="business"`. The demos gallery (`ServicesDemos`) previews the four demo sites with their screenshots from `public/demo-*.webp`, and content comes from `business.demos` in `site.ts`. It is the cold-outreach landing page: keep it benefit-first, mobile-first, and free of stack/DevOps jargon. `Navbar variant="business"` switches the nav; the logo links back to `/`.
- `/demos/retromaquinas` is an isolated buy-and-repair demo: its content, styles, logo, console photo (`ConsoleShot` + `public/playstation-1.webp`), and repair glyphs live in `app/demos/retromaquinas/`. It does not use the portfolio's `Navbar`, `Footer`, `StarField`, or design tokens; everything is scoped under `.rm-root` in `retromaquinas.css`. Its palette is deliberately limited to black, white, and dark blue with an electric-blue accent (do not reintroduce the portfolio's violet/cream tokens); typography is Anton + DM Sans + JetBrains Mono. It shares the global `data-theme`/`useTheme` system so the demo navbar's toggle drives light and dark, and adds its own Google Fonts in the route `links`. The demo form is client-side only (shows a success state, sends nothing); replace the SVG logo and placeholder email/Instagram when real assets exist. The landing plan in `site.ts` links to this demo via its `demo` field.
- `/demos/forjapc` is an isolated five-page institutional demo: `app/routes/forjapc.tsx` is the shared layout (header/footer/theme) and the `forjapc.*` route files are Inicio, Servicios, Nosotros, Builds, and Contacto. Content lives in `app/demos/forjapc/content.ts`, component illustrations in `PartArt.tsx`, and scoped styles in `forjapc.css`. It is a light/graphite showroom with an orange accent and Bricolage Grotesque + Manrope + DM Mono; do not reuse the portfolio's or Retromaquinas' palettes. Its mark is an isometric cube, deliberately unlike Retromaquinas' framed square, and the home opens with a centered hero plus a full-width featured-build band rather than a text-left/image-right split. It also shares the global `data-theme`/`useTheme` system and has its own Google Fonts in the layout `links`. The contact form is a client-side demo. The institutional plan in `site.ts` links to it via its `demo` field.
- `/demos/pulso` is the catalog + admin demo: `app/routes/pulso.tsx` wraps the storefront and admin in the same providers; `pulso.home/catalog/category/product/search/admin` are the pages. Content, seed data, and types live in `app/demos/pulso/content.ts`; the catalog/order state and localStorage persistence live in `store.tsx`; product SVGs are in `ProductArt.tsx`; admin panels are the `DashboardPanel`, `ProductsPanel`, `PortadaPanel`, `CategoriesPanel`, `StatsPanel`, `ActivityPanel`, and `UsersPanel` components. The storefront uses pure neutral whites and grays (R=G=B, no hue cast) with a dark header/hero, Oxanium + Sora, blue as the action color on light surfaces, and mint green only on dark surfaces and the brand; the home uses a category index, featured rail, setup-profile selector, and category tiles rather than copying the reference layout. The admin is fixed light canvas with a dark sidebar and opens on `Resumen`; its tabs are deep-linked with `?tab=` (`resumen`, `productos`, `portada`, `categorias`, `estadisticas`, `actividad`, `usuarios`). `PortadaPanel` edits the hero, the three featured products, and category order/visibility, which the storefront reads from `siteConfig`; every catalog/portada change appends to the activity log (`ActivityList`). It does **not** use the portfolio theme toggle. Data is frontend-only and persists in `pulso-products-v1`, `pulso-categories-v1`, `pulso-order-v1`, `pulso-site-v1`, and `pulso-activity-v1`; reset it from the admin. The catalog plan in `site.ts` links to this demo via `demo`.
- Edit content in `app/data/site.ts`, not in components. `business` holds the `/servicios` copy, plans, prices, extras, maintenance, conditions, quote checklist, cases, and FAQ; the landing, institutional, catalog, and store plans link to their demos through `demo` (the store demo is the external Yogures deployment), and the catalog plan also sets `admin` so `ServicesOffer` renders a second "Ver panel" link to `/demos/pulso/admin`. `profile`, `projects`, `skills`, `experience`, and `education` feed the home. `home.tsx` builds its title and meta description from `profile`; `services.tsx` builds them from `business`.
- Project rendering is data-driven in `Projects.tsx`: only `visibility: "publico"` shows Demo/Admin/Código links; `"confidencial"` and `"privado"` show a status note instead. A gallery is rendered for every project with `images`; `src` values are absolute paths into `public/`, so a new screenshot needs both the file and a `site.ts` entry. Business case studies use `business.cases` with the same `public/` image convention. Existing screenshots are referenced as optimized `.webp` files; keep new images compressed.
- `Pleiades` (`app/components/Pleiades.tsx`) is a shared SVG decoration used by `Hero` and `Projects`; edit star positions/edges in `app/data/constellation.ts`, not in the components.
- `app/root.tsx` owns `<html lang="es">`, Google Fonts links, the error boundary, the pre-paint theme script, and `MotionConfig reducedMotion="user"`. Font families are loaded there and mapped in `app.css` — changing a font requires both.
- Imports use the `~/*` alias for `app/*`, configured in both `vite.config.ts` and `tsconfig.json` paths. `verbatimModuleSyntax` is on, so type-only imports need `import type`.

## Styling and theme

- Tailwind 4 is configured entirely in `app/app.css` (no `tailwind.config.*`). Tokens are defined for `:root` / `[data-theme="dark"]` and `[data-theme="light"]`, then exposed via `@theme inline`; a new token needs both the CSS variable and its `--color-*` / `--font-*` mapping.
- Use the semantic utilities, not raw colors: `bg-bg`, `bg-bg-soft`, `bg-surface`, `bg-glass`, `text-fg`, `text-muted`, `text-faint`, `border-line`, `text-violet`, `text-nova`, `text-nebula`, `text-ocean`, `text-danger`, `font-display`, `font-mono`. Every new style must work in both themes.
- Theme is the `data-theme` attribute on `<html>`, set before paint by an inline script and persisted in `localStorage` under `theme`. `useTheme` reads the DOM attribute instead of keeping source of truth in state; follow that pattern for new theme-aware code. `StarField` watches it with a `MutationObserver`.
- Visual language is deliberate: dark "obsidian" default, mostly sharp corners with hairline borders (the Hero portrait frame is the rounded exception), glass surfaces, mono labels, Pleiades constellation motif. Load `.agents/skills/frontend-design/SKILL.md` before large visual changes; note `.agents/` is gitignored, so skill edits stay local and `skills-lock.json` tracks its upstream source.

## Gotchas

- `VITE_FORMSPREE_ID` in `.env` (template: `.env.example`) enables the contact form. Without it `Contact` renders only the direct channels, with no error. `.env` is gitignored, and Vite inlines the value at startup/build — restart the dev server or rebuild after changing it. The form POSTs straight to Formspree from the browser; the email field maps to `_replyto`.
- On `/servicios`, CTAs point to `#contacto` (Formspree/email); no WhatsApp number is configured. Do not invent a contact number or link. Keep the project-type options in `Contact` aligned with `business.plans`.
- Business prices, timelines, extras, maintenance, and conditions in `site.ts` mirror `tarifas.pdf` at the repo root (a source document, not served). Update both together when rates change; the page states prices in USD and valid for 30 days.
- The Retromaquinas demo is intentionally backend-free: its form only sets a local success state; do not wire a real endpoint or invent a WhatsApp number. It is also visually isolated from the portfolio: black, white, and dark blue only, with Anton/DM Sans/JetBrains Mono. Its light and dark palettes are two variable blocks in `retromaquinas.css` (`.rm-root` and `html[data-theme="light"] .rm-root`), so every visual change needs checking in both themes.
- The Forja PC demo follows the same backend-free rule and must stay visually separate: cool light gray/graphite with an orange accent, Bricolage Grotesque/Manrope/DM Mono. Its theme variables live in `forjapc.css` (`.fj-root` and `html[data-theme="light"] .fj-root`); check both themes when touching it. The `?build=` query param on `/demos/forjapc/contacto` prefills the build interest and reason.
- The Pulso demo uses pure neutral whites and grays (R=G=B; surfaces are `#ffffff`, `#f5f5f5`, `#f2f2f2`) with blue for actions/data, and mint green only on dark surfaces and the brand; keep it that way when adding UI. It intentionally does not follow `data-theme`. Catalog edits, the portada config, the activity log, and the order live in localStorage, so use the admin reset button (or clear the five `pulso-*-v1` keys) to return to seed data. The portada preview inside the admin uses `.pl-hero-preview` to re-declare the store tokens, since store tokens only exist under `.pl-store`. The admin has no auth in the demo; do not present it as a real login.
- This app prerenders during build and runs SSR: never touch `window`, `document`, or `localStorage` during render. Put browser access inside `useEffect` (as `StarField` and `useTheme` do) or it will break `npm run build`.
- All animations must respect reduced motion via `useReducedMotion` / `prefers-reduced-motion`; the canvas starfield stops at one static frame.
- `build/`, `.react-router/`, `.env`, and `.agents/` are generated or ignored — do not edit `build/`, and don't expect skill or `.env` changes to be part of a commit.
- On this Windows machine bare `git` aborts with `dubious ownership` (the repo is owned by Administrators); this also makes tooling report the folder as "not a git repo". Prefix commands with `git -c safe.directory='C:/Users/Usuario/Documents/Programación/portafolio'`.
- UI copy, comments, and commit messages are Spanish; code identifiers are English. Existing history follows Conventional Commits (`feat:`, `chore:`); keep new copy consistent in tone and language.
